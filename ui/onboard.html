Onboard a service

ArchGuard automates the architecture review — the sign-off where a senior architect checks your design. You skip the meeting: you describe your service as a diagram in code, open a pull request, and the review runs itself. Everything here is PR-driven.

1

Draw it as code

Describe your service — its parts and what it talks to — in a C4 / Structurizr model. It's text, so it lives in your repo.

2

Open a PR

That pull request is your architecture submission. No separate document, no meeting to book.

3

Get reviewed automatically

ArchGuard checks your model against the rules that apply to your org, department and team — the same review an architect would give.

4

Onboarded → continuous

Once merged, you're on the map. Every later PR updates the diagram and re-runs the review, so it never goes stale.

Try it: submit an architecture for checkout-api

architecture.dsl your submission 
workspace {
  model {
    checkout = softwareSystem "Checkout" {
      api = container "Checkout API"
    }
    profile = softwareSystem "Profile"
    gateway = softwareSystem "API Gateway"

    web     -> gateway "HTTPS"
    gateway -> api     "routes to"
    api     -> profile "reads profile"  "HTTP · sync"    api     -> profile "profile updates" "events · async"
  }
}
Automated architecture review
  • PASS ORG-GW-002 — traffic enters through the gateway
  • PAY-014 — Checkout must not depend on Profile synchronously Your model calls Profile over HTTP (sync). This rule is inherited from the Payments department.
Suggested fix: read profile data from a local copy kept up to date by events, instead of calling Profile live.

That's the whole loop. The first PR onboards you; every PR after that keeps your architecture-as-code current and re-runs the same review — so the diagram always matches what you actually built.
