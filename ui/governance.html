For architects

Governance

Rules are owned, layered and testable. Higher tiers stay active conjunctively; lower tiers may only add constraints. Ownership is enforced through CODEOWNERS, and every rule ships pass/fail fixtures that run in CI on every policy change.

Tiers & precedence

TierOwnerScopeChange path

Higher tiers win conjunctively; a lower tier can add constraints but not loosen an inherited one. Narrowing a rule's scope is a relaxation and needs an exception — ADR-backed, time-boxed and self-expiring. Expired exceptions become findings again.

Five verdicts

A zero-match selector is UNKNOWN, never PASS — vacuous truth is the most common way an architecture gate silently stops working.

What may block

Closed primitive set

The design vocabulary is deliberately closed. No primitive inspects a value, follows data, or reasons about control flow — that absence is the boundary.

Permanent non-goals

If a fix changes what a line does, it belongs to CodeQL, a linter or a security scanner. ArchGuard consumes their output as evidence; it never re-implements them.
