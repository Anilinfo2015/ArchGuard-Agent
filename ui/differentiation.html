How it's different

The difference from an AI review agent isn't code-vs-prose — it's where the rule lives and whether it's governed. The model proposes at authoring time; a deterministic fitness function decides at runtime.

AI review skill / agentArchGuard

vs threat modeling

Threat modeling is a point-in-time security activity over a hand-drawn diagram; it can't block the PR that violates it. ArchGuard makes the threat model an input: imported trust boundaries annotate the graph, and a staleness rule fires when a PR introduces a new boundary crossing.

vs architecture-test libraries

ArchUnit and friends are the deterministic runners ArchGuard stands on. The additions: authoring in English (compiled and reviewed, not hand-coded), one graph spanning code + model + infrastructure, and enterprise governance — tiers, exceptions, ownership, scorecards.

The one defensible claim

English rules, compiled once into reviewed, version-controlled predicates, replayed deterministically on every PR with no model in the gate, over one graph spanning code structure, declared architecture and deployment topology. Neither half ships elsewhere in this combination.

A skill is a fine way to invoke ArchGuard from the Copilot CLI — it is not a substitute for the governed, compiled predicate behind it.
